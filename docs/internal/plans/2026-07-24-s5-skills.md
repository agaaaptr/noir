# S5 Builtin Skills + Compiler Implementation Plan (`@noir-ai/skills`)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `@noir-ai/skills` — the Noir builtin skill pack (28 canonical `SKILL.md` files, all `noir-` prefixed: 16 full playbooks + 12 valid stubs) plus a copy+validate compiler that emits them to the host, wired so `noir init` / `noir sync` install the pack to `.claude/skills/`.

**Architecture:** New 7th package `@noir-ai/skills` (depends `core` only). Canonical skills live as real markdown under a shipped package-root `builtin/` dir; a `discoverBuiltin()` scanner resolves that dir from `import.meta.url` (works identically in `src/` under vitest and `dist/` when built — `builtin/` is a sibling of both). A compiler `parseFrontmatter` → `validateSkill` (enforces `noir-<kebab>` names + the **description = WHEN** rule) → `compileSkill(target:'claude')` (validate + copy verbatim — a real transformer is S10) → `emitSkillsToDir(dir)`. The claude adapter gains a thin `skillsDir(ctx)`; the CLI `init`/`sync` wire emit to that dir. Skills are playbooks; **discipline comes from the S4 engine's observable gates**, not skill-level rhetoric (§9.1).

**Tech Stack:** TypeScript ESM, vitest, Biome, tsup, `yaml` (already a `core` dep). Reuses `@noir-ai/core` (`paths`, `ProjectId`). No LLM (drafting is S8). No runtime dependency on the predecessor plugin or Superpowers.

**Spec:** `docs/internal/specs/2026-07-24-s5-skills-design.md` (OQ-1…4 resolved; DS-1…7).

## Global Constraints

(Copied from the S5 spec. Every task implicitly includes these.)

- **Format = Claude Code `SKILL.md`** (canonical) + YAML frontmatter (`name`, `description`, optional `references/`). (DS-1)
- **`description` = WHEN, never WHAT.** Frontmatter `description` states the trigger ("Use when…"), not mechanics. The compiler **rejects** a WHAT-description. (DS-2 / §9.1)
- **All skills `noir-` prefixed.** Names match `^noir-[a-z0-9]+(-[a-z0-9]+)*$` and the directory name. (DS-3)
- **Compiler = copy + validate** for Claude (v1). Validate frontmatter, then copy verbatim to `.claude/skills/<name>/`. A real multi-host transformer is S10. (DS-4 / OQ-3)
- **Progressive disclosure = one level.** `SKILL.md` (overview + trigger) → optional `references/*.md`. No deeper doc tree. (DS-5)
- **Enforcement = S4 engine's observable gates**, NOT skill-level rhetoric. Strip Superpowers' `<EXTREMELY-IMPORTANT>` / `SUBAGENT-STOP` / anti-rationalization tables and the predecessor's "HARD GATE / Spine" framing; replace with a quiet note that the S4 gate records the decision. (DS-6 / §9.1)
- **Source = reuse + re-implement native.** Port proven content/patterns from `plugins/noir-workflow/` (~5) + the locally-installed Superpowers skills (~10) + net-new (~13), **re-implemented as self-contained native Noir skills** — no runtime dependency on either source. (DS-7 / OQ-2)
- **Target = `.claude/skills/`** (project-local, host-native load path). (OQ-4)
- **Module = ESM** (`"type":"module"`, relative `.js`, NodeNext). **TDD:** failing test first. **stdout discipline:** no stdout in the compiler/emit path (stderr only). **MCP/skill names:** `noir-` prefix, no dots.

## Port transformation `R` (applied to EVERY ported skill — T2/T3/T4/T5)

The builtin skills are authored by **porting** proven source through one fixed transformation. The source files already exist; the implementer reads the named source and applies `R`. This is not derivation from scratch.

**`R` — predecessor/Superpowers → native Noir skill:**

1. **Frontmatter.** `name: noir-<x>`; `description:` = the spec §3 WHEN-trigger for that skill (from the table in each task — copy it verbatim, it is already WHEN-shaped); **drop** `user-invocable` and `allowed-tools` (the host manages loading; Noir does not constrain tools); keep `references:` only if you author reference files.
2. **Strip predecessor residue.** Remove: `/flow`, `/sync`, `/wrap`, `/checkpoint` slash-command invocations; `workflow/<task>.md`; `noir-workflow.mode` and the auto/rich/lean mode-detection matrix; `ClickUp`/clickup intake; Angular `@uiigateway/*` and `npm run versions`; plugin `references/*.md` path prefixes. (The hygiene test enforces this — see FORBIDDEN_RESIDUE in T2.)
3. **Wire to Noir-native runtime.** Where the source referenced its plugin/MCP, point at Noir's: `.noir/specs|plans|tasks|decisions|audit` artifacts (the S4 `ArtifactWriter` layout), the `noir.checkpoint` + `noir.workflow_status` MCP tools, and the S4 engine's observable gates. Noir memory replaces `agentmemory` references.
4. **Strip ALL-CAPS rhetoric** (§9.1). Remove `<EXTREMELY-IMPORTANT>`, `SUBAGENT-STOP`, "YOU MUST", "HARD GATE", "Spine: Investigate → Confirm → Act", anti-rationalization tables. Replace with a quiet note: *"discipline is observable — the SDD engine records this gate decision."* Keep the procedural substance.
5. **Self-contained.** No runtime dependency on the predecessor or Superpowers. Inline any detail the body needs; link further detail only via `references/*.md` (one level).
6. **description = WHEN** (DS-2). The body may expand on *what*, but the frontmatter `description` stays a trigger.

**Worked examples** (full content) appear inline in T2 (`noir-sync`, predecessor port), T3 (`noir-brainstorm`, Superpowers port), T4 (`noir-explore`, net-new), and T5 (`noir-commit`, stub). Every other skill follows the same `R` from its named source with frontmatter from the task's table.

`packages/skills/src/discover.ts`:
```ts
import { readFileSync, readdirSync } from 'node:fs';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';
import type { BuiltinSkill } from './types.js';
import { parseFrontmatter } from './compiler.js';

// Package root = ONE level up from THIS module's directory. Works in every layout
// because `builtin/` is always a sibling of the dir this code runs from:
//  - vitest:  .../packages/skills/src/discover.ts   -> HERE = src   -> PKG_ROOT = package root
//  - built:   .../packages/skills/dist/index.js     -> HERE = dist  -> PKG_ROOT = package root
//             (tsup bundles everything into dist/index.js; `dirname` still yields `dist`.)
const HERE = dirname(fileURLToPath(import.meta.url));           // .../src  OR  .../dist
const PKG_ROOT = dirname(HERE);                                  // .../packages/skills
export const BUILTIN_DIR = join(PKG_ROOT, 'builtin');

export function discoverBuiltin(builtinDir: string = BUILTIN_DIR): BuiltinSkill[] {
  const dirs = readdirSync(builtinDir, { withFileTypes: true })
    .filter((e) => e.isDirectory() && e.name.startsWith('noir-'))
    .map((e) => e.name)
    .sort();
  return dirs.map((name) => {
    const dir = join(builtinDir, name);
    const skillMd = readFileSync(join(dir, 'SKILL.md'), 'utf8');
    const frontmatter = parseFrontmatter(skillMd);
    const refsDir = join(dir, 'references');
    let references: BuiltinSkill['references'] = [];
    try {
      references = readdirSync(refsDir)
        .filter((f) => f.endsWith('.md'))
        .sort()
        .map((f) => ({ name: f, content: readFileSync(join(refsDir, f), 'utf8') }));
    } catch {
      references = []; // no references/ dir is fine
    }
    return { name, dir, skillMd, frontmatter, references };
  });
}
```
> **Path note:** `discoverBuiltin` resolves the package root as the **parent** of the module's directory. In `src/discover.ts` that parent is `src/..` = package root ✓; in `dist/discover.js` it is `dist/..` = package root ✓. `builtin/` ships at the package root via `files: ["dist","builtin"]`. If you rename/relocate `discover.ts`, re-derive the depth so both `src` and `dist` resolve to the package root.

`packages/skills/src/compiler.ts`:
```ts
import { readdir, mkdir, writeFile, readFile } from 'node:fs/promises';
import { basename, dirname, join } from 'node:path';
import { parse as parseYaml } from 'yaml';
import type {
  BuiltinSkill,
  CompileTarget,
  CompiledSkill,
  EmitSummary,
  SkillFrontmatter,
  ValidationResult,
} from './types.js';
import { discoverBuiltin } from './discover.js';

const FRONTMATTER_RE = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/;
const NAME_RE = /^noir-[a-z0-9]+(?:-[a-z0-9]+)*$/;
const WHEN_START =
  /^(use|using|whenever|when|before|after|while|starting|encountering|completing|creating|about to)\b/i;
const MAX_DESC = 1024;

export function parseFrontmatter(md: string): SkillFrontmatter {
  const m = md.match(FRONTMATTER_RE);
  if (!m) throw new Error('Skill missing YAML frontmatter (expected --- ... ---)');
  const fm = parseYaml(m[1]) as SkillFrontmatter;
  if (typeof fm?.name !== 'string' || typeof fm?.description !== 'string') {
    throw new Error('Skill frontmatter requires string `name` + `description`');
  }
  return fm;
}

export function bodyOf(md: string): string {
  return md.replace(/^---\r?\n[\s\S]*?\r?\n---\r?\n?/, '');
}

export function looksLikeWhenDescription(desc: string): boolean {
  const d = desc.trim();
  if (!d) return false;
  if (WHEN_START.test(d)) return true;
  return /\b(when|before|after|whenever|while)\b/i.test(d);
}

export function validateSkill(skill: BuiltinSkill): ValidationResult {
  const errors: string[] = [];
  const { name, description } = skill.frontmatter;
  if (!name) errors.push('missing `name`');
  else if (!NAME_RE.test(name)) errors.push(`name "${name}" must match noir-<kebab>`);
  if (basename(skill.dir) !== name) {
    errors.push(`dir "${basename(skill.dir)}" must equal name "${name}"`);
  }
  if (!description?.trim()) errors.push('missing `description`');
  else if (description.length > MAX_DESC) errors.push(`description exceeds ${MAX_DESC} chars`);
  else if (!looksLikeWhenDescription(description)) {
    errors.push('description must state WHEN to trigger (e.g. "Use when…"), not WHAT it does');
  }
  for (const r of skill.references) {
    if (!/^[a-z0-9-]+\.md$/i.test(r.name)) errors.push(`reference "${r.name}" must be <kebab>.md`);
    if (!r.content.trim()) errors.push(`reference "${r.name}" is empty`);
  }
  return { ok: errors.length === 0, errors };
}

export function compileSkill(skill: BuiltinSkill, target: CompileTarget = 'claude'): CompiledSkill {
  const res = validateSkill(skill);
  if (!res.ok) throw new Error(`Cannot compile ${skill.name}: ${res.errors.join('; ')}`);
  if (target !== 'claude') throw new Error(`Unsupported compile target: ${target}`);
  // Claude (v1) target = canonical format copied verbatim (DS-4). Multi-host transform is S10.
  const files = [
    { path: ['SKILL.md'], content: skill.skillMd },
    ...skill.references.map((r) => ({ path: ['references', r.name], content: r.content })),
  ];
  return { name: skill.name, files };
}

export async function emitSkillsToDir(
  targetDir: string,
  opts: { builtinDir?: string } = {},
): Promise<EmitSummary> {
  const skills = discoverBuiltin(opts.builtinDir);
  // Validate the whole pack before writing anything (fail-fast, atomic-ish).
  for (const s of skills) {
    const res = validateSkill(s);
    if (!res.ok) throw new Error(`Invalid builtin skill ${s.name}: ${res.errors.join('; ')}`);
  }
  await mkdir(targetDir, { recursive: true });
  let references = 0;
  for (const s of skills) {
    const compiled = compileSkill(s, 'claude');
    for (const f of compiled.files) {
      const dest = join(targetDir, s.name, ...f.path);
      await mkdir(dirname(dest), { recursive: true });
      await writeFile(dest, f.content, 'utf8');
      if (f.path[0] !== 'SKILL.md') references++;
    }
  }
  return { dir: targetDir, emitted: skills.map((s) => s.name), references };
}

// Convenience for callers/tests that already hold raw markdown (unused by emit path;
// kept so adapters/tests can validate a single in-memory skill without a dir).
export { discoverBuiltin };
```

## Notes for the implementer

- **`@noir-ai/skills` is content + a small compiler.** It depends on `core` only. The compiler is pure I/O over a directory (the shipped `builtin/`); it never imports the predecessor plugin or Superpowers at runtime (DS-7).
- **`builtin/` is shipped, not bundled.** `discoverBuiltin()` resolves it from `import.meta.url` (parent of the module dir = package root in both `src` and `dist`). `package.json` `files` includes `"builtin"`. Do not relocate `discover.ts` without re-deriving the depth.
- **description = WHEN is enforced in code.** `looksLikeWhenDescription` + `validateSkill` reject WHAT-descriptions; the hygiene tests gate every shipped skill. When porting, always rewrite the source's verbose WHAT-description to the spec §3 WHEN-trigger (the task tables give it verbatim).
- **Strip, don't transplant, rhetoric.** Superpowers' `<EXTREMELY-IMPORTANT>`/`SUBAGENT-STOP`/anti-rationalization tables and the predecessor's "HARD GATE / Spine" framing are removed and replaced with the quiet observable-gate note. `FORBIDDEN_RESIDUE` lists the tokens the hygiene test rejects.
- **Stubs are real skills.** A stub has a valid WHEN `description`, a body with the `> **Stub:**` marker, and a one-line "For now" pointer. It must pass validation and load in the host.
- **No LLM in S5.** Skill content is authored by porting; the compiler copies + validates. Drafting/generation is S8.
- **stdout discipline:** emit/init/sync report on **stderr** (matching the existing CLI convention). No stdout in the compiler/emit path.
- **Build-before-integration-test:** the CLI integration test (T6) consumes `@noir-ai/skills`' built `dist` + shipped `builtin/`, so run `pnpm -r build` before `pnpm --filter @noir-ai/cli test`. The skills package's own unit tests (T1–T5) import `../src` and need no build.
