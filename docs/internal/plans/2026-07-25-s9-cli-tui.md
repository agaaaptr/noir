## Resolved answers
- Shape: **commander backbone + @clack/prompts interactive home menu** (TTY-gated). Migrate the hand-rolled `parseArgs` dispatcher in `packages/cli/src/bin.ts`. Defer full-screen Ink/blessed TUI to v2.
- Non-interactive: global `--json`/`--no-input`/`--quiet`/`--verbose`/`--cwd`; honor `NO_COLOR`/`CI`/`!isTTY`; **data→stdout, diagnostics→stderr**; exit codes `0 ok · 1 error · 2 usage · 3 not-found · 4 daemon-down · 5 cancelled` via commander `exitOverride` + `configureOutput`.
- Daemon UX: **honest foreground** — `noir daemon start` runs foreground ("backgrounding deferred; Ctrl+C to stop"); `--detach` is recognized but returns "not implemented (tracked: v1.x)" exit 2; `status` reports pid/uptime/mode or "not running" (exit 4 when probed by script).
- Output deps: **picocolors + cli-table3 + ora** (auto-disabled under `--json`/non-TTY/`NO_COLOR`/`CI`).

## Architecture
- Store-touching commands (`context *`, `memory *`, `task *`, `status`) are **MCP clients to the daemon**: `ensureDaemonRunning()` then connect via `@modelcontextprotocol/client` Streamable HTTP and `callTool(...)`. This respects the single-writer daemon and reuses the MCP surface already built. A clear exit-4 error + "run `noir daemon start`" if the daemon is down.
- In-process commands (no store): `init`, `sync`, `skills list`, `daemon start/stop/status`, `doctor`, `mcp serve`.
- New `packages/cli/src/{output.ts, daemon-client.ts, commands/*.ts}`; `bin.ts` becomes a thin commander setup. Behavior-preserving migration of the 5 existing commands.

## Tasks (lean: one implementer each, self-verifies; main loop validates)
- **t1** Deps + commander migration. `packages/cli/{package.json,src/bin.ts}`. Add deps `commander`, `@clack/prompts`, `picocolors`, `cli-table3`, `ora`, `@modelcontextprotocol/client`. Rewrite `bin.ts` as a commander program with `exitOverride` + `configureOutput` (never `process.exit` mid-test); preserve EXACT behavior of `init`, `sync`, `mcp serve [--stdio]`, `daemon start|stop`, `doctor`. Add global options `--json --no-input --quiet --verbose --cwd <p>`. Keep the tsup shebang banner.
- **t2** Output infra. `packages/cli/src/output.ts`. Wrappers: `isInteractive()` (isTTY && !CI && !NO_COLOR && !noInput); `json(obj)` (stdout); `info/warn/error/success` (stderr, picocolors, suppressed appropriately under --quiet/--json); `table(rows)` (cli-table3, suppressed under --json); `spinner()` (ora, auto-disabled non-TTY/CI/--json). Exit-code helper `fail(code, msg)` → stderr + process exit via commander's exitOverride path.
- **t3** Daemon MCP client. `packages/cli/src/daemon-client.ts`. `withDaemon<T>(fn): Promise<T>` — `ensureDaemonRunning()` (from @noir-ai/daemon), connect `Client` over Streamable HTTP to the daemon URL (from ~/.noir/daemon.json), `callTool(name, args)`, return parsed JSON; on any failure (daemon down, transport error) → exit 4 with a clear "daemon not running — try `noir daemon start`" message (unless --json, then JSON error). Reuse the daemon record reader from @noir-ai/daemon.
- **t4** Home menu + status. `packages/cli/src/commands/{home.ts,status.ts}`. `noir` (no arg): if interactive → @clack menu (status + quick actions: index, recall, task next, daemon start); else emit `status --json` or `--help`. `noir status [--json]`: aggregate `host_status` + `store_status` + `context_status` + workflow active task + memory counts via the daemon client; render a table (or JSON).
- **t5** context + memory + task subcommands. `packages/cli/src/commands/{context,memory,task}.ts`. Thin MCP-client commands: `context search <q> [--limit] [--json]`, `context index [--paths]`, `context status`; `memory recall <q>`, `memory save [--type] [--content]`, `memory sessions`, `memory forget <id>`, `memory consolidate` (only if daemon exposes it); `task new`, `task status [<id>]`, `task advance`, `task next` (workflow_status/checkpoint MCP). All support `--json`; human output uses tables + snippets.
- **t6** skills + daemon control + doctor. `packages/cli/src/commands/{skills,daemon-cmd,doctor}.ts`. `skills list` (discoverBuiltin → table), `skills sync` (emitSkillsToDir to the adapter's skillsDir — reuse existing sync). `daemon start [--detach*]` (foreground-honest; `--detach` → exit 2 "v1.x"), `stop`, `status`, `restart`. `doctor`: checks — config parses, daemon reachable, store opens, context embedder available (vecAvailability), **provider status via `resolveModelConfig`** (model/key-present, NO live call), native deps (better-sqlite3, sqlite-vec, onnxruntime-node). Render as a table; exit 1 if any critical check fails.
- **t7** Tests. `packages/cli/test/*.test.ts`. Commander testability: drive the program via `program.parseAsync([...], {from:'user'})` with exitOverride capturing exit codes; assert `--json` stdout is valid JSON + diagnostics on stderr; non-TTY path disables interactive prompts; home menu logic (interactive vs not); daemon-client error path → exit 4 (mock ensureDaemonRunning/MCP); doctor provider-status (no live call). No real daemon in unit tests (mock the client). Existing init/sync/skills-emit/gate1-stdio tests must still pass.
