## 0. Overview

`@noir-ai/context` fills the `EmbedFn` seam S1 declared but never implemented. It indexes project files into the **existing** `docs` + `docs_fts` + `vec0` tables (no schema migration) with SHA-256 content-hash incremental tracking, and answers queries with **BM25 ∪ cosine-kNN fused by Reciprocal Rank Fusion (k=60, 0.5/0.5, rank-based)** packed into a token budget with **window-extracted snippets** (never truncated). Three MCP tools expose it, gated on `ctx.context` exactly as `store_status` is gated on `ctx.store`.

The single-writer daemon owns indexing; a read-only store fallback keeps `context_search`/`context_status` working (live reads off the same handle) while `context_index` surfaces a clear degraded error.

### Global Constraints (every task implicitly includes these)

- **Reuse, don't migrate.** The existing `Store` API is the only storage surface: `indexDoc({id,source,content,meta})`, `searchFt(query,opts)`, `upsertVec(id,vec,{source})`, `knn(vec,opts)`, `countDocs()`, `countVecs()`, `getState<T>/setState<T>` (KV). **No store schema migration.** Same `id` for a chunk's doc row AND its vector (RRF joins on it).
- **`EmbedFn = (text:string)=>Promise<Float32Array>`** is the seam; 384-dim `vec0`. Embeddings **L2-normalized before upsert** (DS-8) so vec0's default L2 distance ≈ cosine.
- **RRF k=60, weights 0.5/0.5, rank-based** — `score(d)=Σ wᵢ/(k+rankᵢ)`. NEVER normalize/sum raw BM25+cosine scores. A doc in only one list gets only that term.
- **Canonical `ProjectId` only** (never a filesystem path). In-process only (no sidecar). Never truncate snippets (FTS5 `snippet(docs_fts,0,'<<','>>','…',16)` window-extract).
- **Lazy model load.** `@huggingface/transformers` is imported via dynamic `import()` inside `localEmbedder` so CLI startup + non-context paths stay offline/fast. Load failure ⇒ BM25-only with `degraded:true, mode:'bm25-only'` (F8), never a crash.
- **Module = ESM** (`"type":"module"`, relative `.js` in imports, NodeNext). **TDD:** failing test first. **MCP/skill names:** `noir-` prefix where applicable, tool names match `^[a-zA-Z0-9_-]+$` (NO dots).
- **MCP registration pattern:** `server.registerTool(name,{description,inputSchema:ZodRawShape},async(args)=>({content:[{type:'text',text:JSON.stringify(payload,null,2)}]}))`; wrap errors via the existing `textResult({ok:false,degraded:true,error})` helper; gate registration on `ctx.context` presence.

### Task t4 — Chunker

**Depends on:** t2 **Files:** `packages/context/src/chunker.ts`

**Approach:** `chunkFile({path, content, language}): Chunk[]` dispatches on extension: `.md`/`.mdx` → markdown-heading split (split on `^#+\s` lines, keep heading + body together, emit one chunk per section); everything else → line/token-bounded windows (~512 tokens, 64 overlap) via a cheap whitespace/line approximation. ### Task t5 — RRF fusion

**Depends on:** t2 **Files:** `packages/context/src/rrf.ts`

**Approach:** `fuseRrf(bm25: FtsHit[], knn: VecHit[], opts?: {k?:60, weights?:[0.5,0.5]}): {id, source, score}[]` — for each unique `id`, `score = Σ weights[i]/(k + rankᵢ)` where `rankᵢ` is 1-based position in list `i` (a doc absent from a list contributes nothing — no penalty, no normalization). Sort descending by score, tie-break by first-seen rank. Pure function, fully deterministic (NFR-5).

## 4. Testing Strategy

- **Deterministic by default.** Every unit test uses `fakeEmbedFn` (hash → 384-dim unit vector); the suite runs fully offline (NFR-2). No test depends on MiniLM weights or the network.
- **Guarded real-model test.** One integration test probe-loads `@huggingface/transformers` at module load and `describe.skip`s with a labelled reason if absent — mirrors `packages/store/test/vec.test.ts`'s `VEC_PROBE` pattern exactly.
- **MCP round-trip.** `context-tools.test.ts` uses the `InMemoryTransport.createLinkedPair()` + `Client` pattern from `store-status.test.ts` to exercise the real `registerTool` schema + handler path (no HTTP, no stdio).
- **Degraded paths.** Explicit tests for BM25-only (`kind:'none'` / embed throw) and read-only store (`context_index` error envelope, `context_search` still works).
- **Determinism of ranking.** RRF tests assert identical inputs ⇒ identical ordering (NFR-5, AC-3).

## 6. Risks & Mitigations

- **Lazy-load still blocks startup if mis-placed.** Mitigation: `localEmbedder` does the dynamic `import()` inside the function body, not at module top; the context package is never imported by `core`/`cli` startup paths (only by `daemon` which already imports `store`/`workflow`).
- **vec0 dimension mismatch / non-normalized vectors silently degrading kNN.** Mitigation: `l2normalize` is mandatory in `createEmbedFn`; `ctx:embedder` KV records `{kind,model,dim}` and the engine warns on mismatch (never silent).
- **Core→context import cycle.** Mitigation: core owns the user-facing zod schema; context owns the `EmbedderConfig` factory type + a `resolveEmbedderConfig` mapper. Core never imports context.
- **Single-writer violation.** Mitigation: the indexer/retriever take the injected `Store` handle; `ContextEngine` is the only context writer; `--watch` is opt-in and serialized through the daemon's event loop (F5).
- **Snippet truncation regression.** Mitigation: retriever tests assert window-extraction (F7); BM25 hits reuse `FtsHit.snippet` verbatim.
- **Remote embedder leaking source to cloud by default.** Mitigation: `remote`/`ollama` are `kind:`-explicit opt-in; default is `local`; `kind:'none'` is the safe fallback (NFR-1).

## 7. Notes for the implementer

- **Mirror existing seams precisely.** `context-seam.ts` = `workflow-seam.ts` shape; the `if (ctx.context)` block in `server.ts` = the `if (ctx.engine)` block; `stdio.ts`/`http.ts` injection = the `engine` spread. Copy the comments' framing (single writer, one-per-lifecycle, degraded story).
- **KV key discipline.** Prefix all context KV with `ctx:` (`ctx:file:<path>`, `ctx:registry`, `ctx:embedder`) — the store KV is shared with workflow (`workflow:*`); keep namespaces disjoint.
- **Chunk id stability.** `<sha256(path)>#chunk-<n>` must be deterministic across re-indexing so content-hash skips and deletes are exact.
- **Identifier explosion is index-time only.** Append `explodeIdentifiers` to chunk `content` before `indexDoc` + `embed`; do not store it in `meta` (it pollutes BM25 otherwise only at query time — we want index-time).
- **Don't over-build remote/ollama.** They are provider-explicit stubs that compile and throw clear "not configured" errors; full provider SDKs are post-v0.
