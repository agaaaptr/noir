## Resolved answers
- Providers v1: **anthropic + openai + openai-compatible** (Ollama/local via `baseURL`).
- Structured output: **prompt-based JSON + JSON-Schema validate + ≤1 retry** (native strict modes deferred).
- Per-tier models: cheap (draft/title/summarize), mid (consolidate); IDs live in config.
- Provider config: `.noir/config.yml` `model:` block; secrets in env vars (config stores the env-var NAME).
- `noir doctor` reports provider status (model, key-present, last usage; no live call).
- retries=0 (SDK); maxTokens draft 2048 / title 64 / summarize 512 / consolidate 2048.
- NO streaming, NO `tools` param (agent loops impossible by construction). Prompt-caching deferred to v1.x.

## Architecture
- New package `@noir-ai/model` (9th). Library only — **no MCP tools**.
- One function: `complete(req: CompleteRequest): Promise<CompleteResult>` where result is `{ ok: true, text/object, usage } | { ok: false, reason } | null` (null = no provider configured → degrade).
- Adapters: `anthropic` (@anthropic-ai/sdk Messages), `openai` (openai SDK chat.completions), `openai-compatible` (global `fetch` to `${baseURL}/chat/completions`).
- Consumers (later slices): S7 consolidation, S4 artifact drafting, S9 home help. S8 just provides the library + config; minimal consumer wiring is folded into those slices.

## Tasks (lean: one implementer each, self-verifies; main loop validates)
- **t1** Scaffold `@noir-ai/model` + types + `complete()` shell w/ null-degradation.
  files: `packages/model/{package.json,tsup.config.ts,tsconfig.json,src/index.ts,src/types.ts,src/complete.ts}`. Mirror workflow scaffold. Types: `CompleteRequest{system?,prompt,schema?,provider,model,maxTokens?}`, `CompleteResult` (discriminated ok/null), `ProviderAdapter`, `ModelConfig`. `complete()` dispatches on provider; returns null when none configured.
- **t2** Anthropic adapter. `packages/model/src/providers/anthropic.ts`. @anthropic-ai/sdk; Messages API single-shot; no `tools`; maxTokens; returns `{text, usage{input,output}}`.
- **t3** OpenAI + OpenAI-compatible adapters. `packages/model/src/providers/{openai,openai-compatible}.ts`. openai SDK for `openai`; global `fetch` for `openai-compatible` (Ollama `baseURL`). Same result shape.
- **t4** Structured output + provider dispatch. `packages/model/src/{structured.ts,complete.ts}`. prompt-based JSON (instruct model to return JSON matching schema) → parse → validate against JSON Schema (use `ajv` or a tiny validator; NO heavy dep if avoidable — prefer a minimal hand-rolled validator or zod-from-schema) → ≤1 retry on parse/validate failure. Wire provider selection + null-degradation into `complete()`.
- **t5** Config. `packages/core/src/config.ts` (+ `packages/model/src/config.ts` resolver). Add `model:` block to `NoirConfigSchema` mirroring `daemon:`: `{ defaultProvider?: string, tiers?: {draft?,title?,summarize?,consolidate?}, providers?: Record<string,{model,baseURL?,apiKeyEnv?}> }.default({})`. `resolveModelConfig(NoirConfig['model'])` bridge (core→model, no cycle). Reads keys via `process.env[apiKeyEnv]`; provider-explicit only.
- **t6** Tests (offline). `packages/model/test/*.test.ts`. null-degradation when no provider/key; prompt-JSON validate+retry (fake model responses); adapter request SHAPE with mocked fetch/SDK (NO real network); provider-explicit-only (never infers from env presence); per-tier maxTokens defaults; usage passthrough.
