## Display integrity + workspace transport + permission contract + output hygiene (2026-09-24 → unreleased)

> **Implemented on `develop` 2026-09-24/25; not yet published.** Spec `2026-09-24-display-transport-permission-hygiene-design.md`; ADR-0013 (workspace transport via the stdio bridge + `400` for a misdirected workspace URL). The full gate runs as the milestone's final step; upgrade notes are in `CHANGELOG.md`.

- ✅ **Terminal rendering breaks its own layout** — RESOLVED: one shared display-width module (`packages/cli/src/width.ts`) is the single authority for measuring terminal text (ANSI stripped, East-Asian wide/fullwidth measured as 2 columns, truncation never splitting a surrogate pair or grapheme), and every renderer, `output.ts` table and status line measures through it. Width budgets derive from the container rather than hard-coded constants, tables never exceed the terminal (columns floor, then the row is ellipsised) and path-like values middle-truncate. `--quiet` now actually turns decoration off: `bin.ts` bridges the flag to `NOIR_QUIET`, which the colour authority reads (quiet above `CLICOLOR_FORCE`, `NO_COLOR` still wins).
- ✅ **A workspace daemon cannot be reached by a host** — RESOLVED (ADR-0013): a joined repo's `.mcp.json` `noir` entry is a stdio bridge (`noir mcp serve --stdio --workspace <name>`) instead of a `?p=` URL with no credential; the bridge verifies ownership through `/health`, reads the `0600` token, and relays both directions. A project daemon answers `400` with the flavour mismatch for a workspace-shaped query-string URL (and `405` with `Allow` for a known path with an unsupported method); `noir workspace stop`/`status` prove ownership through `/health`; join/leave preserve user `headers`/`headersHelper`/`env`; `sync`/`--force` no longer downgrade a joined repo; and `init --upgrade` migrates a legacy http entry via the `1.2.0 → 1.3.0` scaffold migration.
- ✅ **`.noir/.env` never becomes owner-only** — RESOLVED: mode `0600` is re-asserted on every command that can touch the file (`init`, `create`, `sync`, `init --upgrade`, `init --force`), healing a pre-existing `0644` file, and the heal is reported once. The store database and its parent directory are created owner-only (`0600` / `0700`, a no-op where the platform has no POSIX bits), and the diagnostic reports the observed mode with every permission bit evaluated plus the cause — replacing the incorrect claim that a `writeFileSync` mode "survives any umask".
- ✅ **Nothing constrains agent output quality** — RESOLVED: a tiered rule source (`packages/skills/src/hygiene.ts`) extends the predecessor-residue scanner rather than duplicating it; deterministic patterns fail, judgement patterns warn only. It is enforced through the skills quality gate (`noir skills lint`), a `noir doctor` check, and this repository's CI (`pnpm hygiene:gate`, the same `scanOutputHygiene` the doctor reports). The `noir-code-hygiene` builtin carries the guidance (28 skills: 27 builtins + 1 integration) and a host-neutral seed template reaches every host; evals for the skill assert against real output; `rules.enabled` now gates emission, host import and the migration refresh.
- ✅ **Documentation accuracy obligation** — RESOLVED: `docs/how-to/shared-workspaces.md` rewritten around the stdio bridge, the reference docs regenerated, ADR-0013 recorded, and a repo-wide comment + documentation sweep removed decorative banner comments and internal shorthand (with the planning corpus exempt by construction). `pnpm docs:validate` is the gate.
- ✅ **`noir create --force` over an existing tree does not run the `.noir/.env` mode heal** — RESOLVED: `create` reports the heal exactly as `init` and `sync` do, so `create --force` (or a re-run) over an existing tree re-asserts `0600` on a file an earlier version left group-readable; `packages/create/test/env-mode.test.ts` pins both the `init --force` and the `create --force` cases. The earlier exclusion held only while `--force` was assumed to target a fresh tree. The heal line still prints before the command's own headline, and that is deliberate: it is emitted before the already-initialized no-op returns, because a permission fixed without a word is the silent drift the re-assert exists to end.
- **50 warn-tier `long-comment-block` findings are accepted, not untracked** — ACCEPTED (judgement tier), recorded so the number is not read as an unnoticed regression. The rule fires on a run of 12 or more consecutive comment lines, and the repository keeps that many in 34 files (mostly module headers and the store/engine seams) where the block is a real explanation rather than narration. None is fail-tier, so none blocks; they stay visible in `pnpm hygiene:gate` output and in the `noir doctor` hygiene row, and the standing guidance is to re-read one when its file is next edited rather than sweep them. Adding a rule never lifts this: the count moves only when a block is actually shortened.
- **Overlay and notice text is not truncated inside the panel** — OPEN, deferred to a separate TUI surface pass. A long path in a post-run overlay value, result or header line wraps inside the panel at narrow widths; the same class exists on the app-level notice line. The milestone truncated the surfaces its brief named (the focused row, the footer, the divider, the run-status line), so this is a follow-up, not a regression.
- **`noir workspace stop` has no escape hatch for a permanently stale record** — OPEN, recorded. Ownership is proven through `/health`, so a record whose pid now belongs to a long-lived unrelated process refuses forever until the record file is deleted by hand. A `stop --force` is the obvious remedy; it is not needed for the failure the ownership proof fixes (signalling the wrong process), so it is parked rather than half-built.

## Daemon hardening + `noir init` completeness + `.noir/.env` precedence (2026-09-11 → 1.14.0)

> **Shipped 2026-09-11 as 1.14.0 (latest + beta).** Spec `2026-09-11-daemon-hardening-init-completeness-design.md`; ADR-0010 (records + HTTP auth) + ADR-0011 (`.noir/.env` precedence + doctrine). Full gate green (1955 tests).

- ✅ **Per-project daemon records** — RESOLVED: `~/.noir/daemons/<projectId>.json` replaces the single global `~/.noir/daemon.json`; the `wrongProject` guards are deleted because foreign-record access is impossible by construction. The legacy file is read exactly once by a self-deleting migration. `NOIR_DAEMON_DIR` is the isolation override.
- ✅ **Configured daemon port** — RESOLVED: `daemon.port` is threaded to the HTTP listener as a *preference*; `EADDRINUSE` degrades to ephemeral with a warning, and the record always names the port actually bound.
- ✅ **Daemon auth token** — RESOLVED: a fresh 32-byte token per start, written `0600` to `~/.noir/daemons/<scopeKey>.token`, enforced on `/mcp` with a constant-time compare; `/health` stays token-free; `noir daemon token` prints it for a host `headersHelper`. Workspace daemons are keyed by workspace name.
- ✅ **Connect-triggered activation** — RESOLVED (Part D): `withDaemon` is connect-first on the project path, spawning only on `ECONNREFUSED` with bounded backoff; the workspace path stays probe-only per ADR-0009 §11.
- ✅ **`.noir/.env` produced by `noir init`** — RESOLVED: seeded at `0600` containing only comments; `.env.example` aligned with the full variable reference; git-tracked files refused outright; `noir env` + doctor report per-key provenance.
- ✅ **`noir init --upgrade` backfills missing seeds** — RESOLVED: `--upgrade` emits every manifest mode except `mergeJson` (`skipIfExists` is create-only-if-absent, so it backfills without touching a user's file); `CURRENT_SCAFFOLD_VERSION` `1.0.0 → 1.1.0` with the first real migration entry.
- ✅ **Ignore-manager default list cleanup** — RESOLVED: the vestigial `/.noir/*.sock`, `/.noir/daemon.pid`, and `/.noir/state/` entries are gone (no socket is ever created, the pid lives in `~/.noir/daemons/`, `.noir/state/` never existed).
- **Windows case-insensitivity of the `.noir/.env` deny-list** — OPEN, deferred by decision. `PROCESS_INJECTION_ENV_RE` is case-sensitive and the refusal is keyed on the literal spelling, while `process.env` on Windows is case-insensitive: `noir_daemon_dir=…` therefore lands in the overlay as a distinct key while the daemon's read still resolves the denied name. A fix needs a case-folding decision (fold the key, or fold the comparison) plus a Windows-run test the suite cannot do offline; recorded rather than half-fixed.
- **`.env` filename case-collision** — OPEN, deferred by decision. The git-tracked refusal asks git about the literal pathspec `.noir/.env` while the loader opens `join(root, '.noir', '.env')`; on a case-insensitive filesystem a tracked `.noir/.ENV` would be *read* as `.env` but asked about as a different name, which can silently disable the refusal on that platform only. Same class as the separator bug fixed in `git-tracked.ts` (a POSIX literal that git cannot match reports a tracked file as untracked); needs a real case-insensitive-filesystem run to verify a fix.
- **`.claude/settings.local.json` policy for `--upgrade`** — OPEN, deliberately recorded. The file is user-owned and `mergeJson` is excluded from `--upgrade` (an upgrade emit would resurrect a `SessionStart` hook the user removed). The accepted consequence: a project initialized before C3 that never had the hook does not receive it via `--upgrade` — only a fresh `noir init` or `--force` writes it. No owner, no scheduled slice; revisit if the hook proves load-bearing for old projects.
- **`listProjectDaemonRecords` has no production consumer** — OPEN, recorded rather than dropped. `packages/daemon/src/project-record.ts:54` is exported from `packages/daemon/src/index.ts` and exercised by `project-record.test.ts`, but nothing in `packages/{daemon,cli}` calls it: the spec's `noir daemon status --all` never shipped, and the only per-record readers are the single-project `readProjectDaemonRecord` paths. It is a small, tested, importable seam — kept deliberately (a future `daemon status --all` / doctor sweep is the obvious consumer) rather than deleted to satisfy a coverage metric, but it is dead surface today and should not be described as powering anything.
- **Part D (connect-triggered activation) was NOT deferred** — the design allowed this part to be dropped if it turned out to add complexity without a measurable win; that escape hatch did not trigger: `withDaemon` is connect-first on the project path and the workspace path is untouched. Recorded here so the escape hatch is not mistaken for a taken decision.
