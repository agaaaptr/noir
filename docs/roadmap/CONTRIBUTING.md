# Contributing to the Noir Roadmap

The roadmap is a **living document** that changes when there is new research, a new engineering workflow, a new AI host/standard, an architecture improvement, or new technical debt. This file is scoped to **roadmap edits** — for contributing code to the repo, see the root [`CONTRIBUTING.md`](../../CONTRIBUTING.md).

## Before changing the roadmap

1. Audit the roadmap, codebase, specifications, and technical debt.
2. Do web research (multiple sources, synthesized — never one source).
3. Analyze trade-offs and prepare a proposal.
4. Review before applying.

## Rules

- **Do not** add a capability without research.
- **Do not** remove a capability without reason.
- **Do not** change architecture without an ADR.
- **Do not** write the roadmap from assumptions.
- **Do** keep the philosophy + lifecycle in `README.md` (single source) — capability docs reference, never restate.
- **Do** keep `STATUS.md` and `roadmap.manifest.yaml` in sync.
- **Do** record every change in [`CHANGELOG.md`](CHANGELOG.md) with a reference (ADR / spec / research).
