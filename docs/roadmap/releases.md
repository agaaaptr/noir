## Current status

Remaining v2.0 ecosystem (memory cloud sync, team, skill registry, theming) stays long-term.
>
> **`1.14.0` — daemon hardening + `noir init` completeness + `.noir/.env` precedence (spec `2026-09-11-daemon-hardening-init-completeness-design`, ADR-0010 + ADR-0011): published on `latest` and `beta`.** The daemon record becomes per-project (`~/.noir/daemons/<projectId>.json`; the global `~/.noir/daemon.json` is read once by a self-deleting migration, then gone), `daemon.port` is honoured as a preference (ephemeral fallback on `EADDRINUSE`, record always names the bound port), the Streamable HTTP transport requires a token minted fresh per start at `0600` (`/health` stays token-free; `noir daemon token` feeds a host `headersHelper`), and `withDaemon` is connect-first on the project path. `noir init` writes `.noir/.env` at `0600` and `.noir/README.md`, `.env.example` gains the full variable set, the vestigial ignore entries are dropped, and `--upgrade` backfills every absent seed (`CURRENT_SCAFFOLD_VERSION` `1.0.0 → 1.1.0`). **Two independent breaking changes** — the on-disk record layout, and the inverted `.noir/.env` rule: **the project file now wins for every key it defines**, the real environment is the fallback. Upgrade notes (including the workspace `.mcp.json` re-establish step) are in `CHANGELOG.md`.
>
> **`1.15.0` — env templates + `noir init --upgrade` completeness + provider gateways + `noir run` UX (spec `2026-09-14-env-templates-upgrade-provider-run-ux-design.md`, ADR-0012): published on `latest` and `beta` (as `1.15.0-beta.1`).** The `.noir/.env` and `.noir/.env.example` templates are split by purpose (a short all-comment activation sheet vs. the detailed reference) and carried to existing projects by a `1.1.0 → 1.2.0` scaffold migration; `noir init --upgrade` gains `refreshIfStale` (a byte-exact template-history registry that regenerates unedited seeds, conflict-prompts edited ones, and preserves unreadable ones) plus host-aware artifact emission and honest skill reporting, and legacy stamp-less projects run their migrations. The model layer gains `authTokenEnv`/`timeoutMs` provider fields and honors `baseURL` on **both** adapters, while neutralizing the SDK's ambient-env fallbacks (`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`, `OPENAI_BASE_URL`) — a **narrow breaking change** for anyone who relied on that accidental path. `noir run` grows a TTY status line, palette argument collection, an in-process TUI run mode, a post-run action menu, and an interrupt contract (`SIGTERM`→5 s→`SIGKILL`, transcript-on-interrupt, exit 130/143); `noir env` reports the gateway variables. The `run.profiles.<n>.env` injection deny-list closes a profile-env `spawn` hole. Upgrade notes are in `CHANGELOG.md`.
>
> **`1.16.0` — display integrity + workspace stdio transport + permission contract + output hygiene (spec `2026-09-24-display-transport-permission-hygiene-design.md`, ADR-0013): the current release, published on `latest` and `beta` (as `1.16.0-beta.1`; 2026-09-25).** **Display integrity:** one shared display-width module (`packages/cli/src/width.ts`) becomes the single authority for measuring terminal text — ANSI stripped, East-Asian wide/fullwidth measured as 2 columns, truncation never splitting a surrogate pair or grapheme — and every renderer, the `output.ts` tables and the run-status line measure through it; width budgets derive from the container (post-run overlay, dashboard divider, footer), tables never exceed the terminal and ellipsise over-long rows with path-like values middle-truncated, and `--quiet` now actually disables decoration. **Workspace transport (breaking for joined repos):** the host reaches a workspace daemon through the stdio bridge (`noir mcp serve --stdio --workspace <name>`) instead of a `?p=` URL in `.mcp.json`; a project daemon answers `400` for a misdirected workspace URL (and `405` for a known path with an unsupported method); `noir workspace stop`/`status` prove ownership through `/health`; join/leave preserve user wiring; `sync`/`--force` no longer downgrade a joined repo; and `noir init --upgrade` migrates a legacy http entry (a `1.2.0 → 1.3.0` scaffold migration). **Permission contract:** `.noir/.env` is re-asserted `0600` on init/create/sync/upgrade/force (healing an existing `0644` file), the store database and its parent directory are created owner-only, and the diagnostic names the observed mode and its cause. **Output hygiene:** a tiered rule source drives `noir skills lint`, a `noir doctor` check, and a CI gate (`pnpm hygiene:gate`); a new `noir-code-hygiene` builtin (27 builtins + 1 integration = 28 skills); a host-neutral rules seed; `rules.enabled` now gates emission, host import and migration refresh; evals assert real output; and a repo-wide comment and documentation sweep removed decorative banners and internal shorthand. Upgrade notes are in `CHANGELOG.md`.
>

**The platform today (shipped & working):**
- **11 packages** `@noir-ai/{core,store,workflow,skills,daemon,adapters,cli,context,model,memory,create}`, unified versioning, npm with SLSA provenance, dist-tags `latest` + `beta`.
- **Native installer** — managed-Node (not single-binary; ADR-0005): `install.sh` (POSIX) + `install.ps1` (Windows PowerShell) provision a pinned Node 22.x runtime under `~/.noir/`, install into an isolated prefix, write a `noir` shim, record `~/.noir/install.json`. No system Node, no `sudo`/admin. Release artifacts carry `SHA256SUMS` + a Sigstore build-time attestation (`gh attestation verify`).
- **CLI self-update + migration** — `noir install`/`migrate` (move an existing install to native, settings preserved, `--uninstall-prev` explicit, never auto-uninstalls); `noir update` (reinstall via the active method); async cached startup version check (24h default) with `NOIR_DISABLE_UPDATE_CHECK` / `NOIR_DISABLE_UPDATES` kill-switches; semver downgrade guard; `noir doctor` install row (advisory, no network).
- **Homebrew formula + Scoop manifest** — real `url`/`sha256`/`version` from the published npm tarball; stable-only (single-channel taps). winget/Chocolatey deferred (ADR-0005).
- **27 builtin `noir-` skills** + **1 integration** (`noir-clickup`) — a copy+validate compiler with a structural quality gate and WHAT+WHEN descriptions, emitted idempotently via `noir init`/`sync` (no plugin, no marketplace — see ADR-0002).
- **SDD workflow engine** — FSM (Intake→Clarify→Spec→Plan→Execute→Verify→Document) with observable, escapable gates (spec/plan/verify), Full/Quick modes, cross-session resume (`noir task resume`), evidence-backed verify gate (HARD/SOFT tiering), soft PRD gate (taskClass-keyed, `noir task new --class`), research grounding sub-step, `noir task verify` (run config checks + submit evidence), `noir task block|abandon`, `noir task decompose` (capability→slice), `.noir/` artifacts, `workflow_*` MCP tools (status/start/advance/resume/block/abandon/research-record), and `noir release` guided orchestrator.
- **Hybrid context retrieval** — BM25 ∪ kNN → RRF, local 384-dim embeddings by default (zero API key), remote/Ollama embedders opt-in.
- **Cross-session memory** — save/recall/search/sessions/forget/consolidate, hybrid retrieval reuse, provider-gated consolidation that refuses cleanly without a provider.
- **Bounded model layer** — single-shot `complete()`, 3 adapters, provider-explicit, agent loops impossible by construction.
- **Local daemon** — single-writer store, stdio + Streamable HTTP transports, read-only FS fallback, 24 MCP tools. Per-project records at `~/.noir/daemons/<projectId>.json`, a configured `daemon.port` honoured as a preference, a `0600` bearer token enforced on the HTTP transport, and connect-first activation (ADR-0010). A workspace daemon is reached through a stdio bridge (`noir mcp serve --stdio --workspace <name>`), a project daemon answers `400` for a workspace-shaped query-string URL, and `workspace stop`/`status` prove ownership through `/health` (ADR-0013).
- **5 host adapters** — `claude`/`agents-md`/`gemini`/`cursor`/`opencode` via `resolveAdapter(host)` + universal `AGENTS.md` emitter (ADR-0004).
- **CLI** — commander command tree, `@clack` home menu, Ink `noir tui` (v2 single-surface palette — `commands`/`output`/`help` corpora; home/help/search merged), `noir run <prompt>` (v2 headless host-driving), `noir doctor` (incl. install row), `noir install`/`migrate`/`update`, `daemon start --detach` (real backgrounding), `context index --force`, `init`/`create`/`sync --dry-run`/`--preview`, in-process read fallback, stable exit codes, `data → stdout / diagnostics → stderr`. Every terminal string is measured through one shared display-width module (tables stay inside the terminal, path-like values middle-truncated), and `--quiet` disables decoration.
- **Release automation** — version-string-based beta/stable dist-tag (a `vX.Y.Z<prerelease>.N` tag publishes to `beta`, a plain `vX.Y.Z` tag publishes to `latest`; the branch is only cross-checked and never selects the channel), auto-prerelease versioning, version registry, smart release tooling, installer artifacts + checksums + Sigstore attestation.

- **v1.15.0 (2026-09-16)** — **env templates + `noir init --upgrade` completeness + provider gateways + `noir run` UX.** The two env templates split by purpose — `.noir/.env` is a short all-comment activation sheet, `.noir/.env.example` the detailed reference — carried to existing projects by a `1.1.0 → 1.2.0` scaffold migration. `noir init --upgrade` gains `refreshIfStale` (a byte-exact template-history registry: regenerate a seed the user never edited, conflict-prompt an edited one, preserve an unreadable one, and run legacy migrations for a project predating the stamp) alongside host-aware artifact emission and honest skill reporting. `model.providers.<name>` gains `authTokenEnv` + `timeoutMs` (min 1000) and `baseURL` is now honoured by **both** the anthropic and openai-compatible adapters, while the SDK's ambient env fallbacks (`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`, `OPENAI_BASE_URL`) are neutralized — a **narrow breaking change** for anyone relying on that accidental path; `noir env` reports the gateway variables. `noir run` gains a TTY-gated stderr status line, palette argument collection (commander introspection, fixing every dead palette leaf), an in-process TUI run mode with a transcript picker, a post-run action menu (memory/research/handoff/resume/save; `--json` gains `answerText`), and an interrupt contract (`SIGTERM` → 5 s → `SIGKILL`, transcript-on-interrupt, exit 130/143, and a one-shot verdict claim so `--json` emits a single envelope). Security: the `run.profiles.<n>.env` deny-list closes a profile-env `spawn` injection hole. ADR-0012. Spec `2026-09-14-env-templates-upgrade-provider-run-ux-design.md`. Gates green (2253 tests).
- **v1.16.0 (2026-09-25)** — **display integrity + workspace stdio transport + permission contract + output hygiene.** One shared display-width module (`packages/cli/src/width.ts`) becomes the single authority for measuring terminal text (ANSI SGR stripped, East-Asian wide/fullwidth counted as 2 columns, truncation never splitting a surrogate pair or grapheme); every renderer, `output.ts` table and the run-status line measures through it, every width budget derives from its container (post-run overlay, dashboard divider, footer), tables stay inside the terminal (columns floor, then the row is ellipsised) with path-like values middle-truncated, and `--quiet` now actually disables decoration (`bin.ts` bridges the flag to `NOIR_QUIET`, which the colour authority reads; `NO_COLOR` still wins). **Breaking for joined repositories:** a workspace `.mcp.json` `noir` entry moves from a `?p=` URL to the stdio bridge (`noir mcp serve --stdio --workspace <name>`), which resolves the workspace daemon, proves ownership through `/health`, reads the `0600` token and relays both directions; a project daemon answers `400` for a misdirected workspace URL and `405` with `Allow` for a known path with an unsupported method; `noir workspace stop`/`status` prove ownership through `/health`; join/leave preserve user `headers`/`headersHelper`/`env`; `sync`/`--force` no longer downgrade a joined repo; and `noir init --upgrade` migrates a legacy http entry (a `1.2.0 → 1.3.0` scaffold migration). **Permission contract:** `.noir/.env` is re-asserted `0600` on init/create/sync/upgrade/force (healing a `0644` file), the store database and its parent directory are created owner-only, and the diagnostic reports the observed mode and its cause. **Output hygiene:** a tiered rule source drives `noir skills lint`, a `noir doctor` check and a CI gate (`pnpm hygiene:gate`); a new `noir-code-hygiene` builtin (27 builtins + 1 integration = 28 skills); a host-neutral rules seed; `rules.enabled` now gates emission, host import and migration refresh; and a repo-wide comment + documentation sweep removed decorative banners and internal shorthand. ADR-0013. Spec `2026-09-24-display-transport-permission-hygiene-design.md`. Gates green (2565 tests).

## Version targets

### v0.x — Foundation & Walking Skeleton  *(shipped)*
**Slices S0–S2.** Monorepo, branding, `.noir/` store, SQLite/FTS5 stores, auto-managed daemon + Noir MCP server (stdio + HTTP).
- **Milestone:** a host CLI connects to Noir over MCP and a tool round-trips. — **MET.**

### v1.0 — Sharp Solo Experience  *(shipped)*
**Slices S3–S9.** Claude Code adapter + scaffolder, SDD workflow engine, builtin skills + compiler, context management, memory management, bounded model layer (optional), polished-but-minimal TUI home screen.
- **Target user:** a solo power-user doing idea → spec → plan → implementation inside **Claude Code**, with persistent cross-session memory.
- **Host scope:** **Claude Code only** (behind an abstract `HostAdapter` so generalization is later mechanical, not architectural). — **MET.**

### v1.x — Cross-CLI & Distribution  *(shipped)*
**Slices S10–S11.** Additional host adapters (OpenCode, Gemini, Agy, Qwen) with per-host emulation; npm publish (`@noir-ai/*`); `noir doctor`; framework docs; SDK surface ("usable as a framework").
- **Milestone:** true cross-CLI + installable product. — **MET** (5 adapters shipped; `qwen`/`agy` deferred — universal `AGENTS.md` covers them).
- **v1.13.0 — shared cross-repo workspaces** (ADR-0009): one workspace daemon serving a shared cross-repo memory store (`start --workspace` / `join`, `?p=` routing, change feed, manual `noir memory capture`). Localhost, single-machine. — **MET.**
- **v1.14.0 — daemon hardening + `noir init` completeness + `.noir/.env` precedence** (ADR-0010 + ADR-0011): per-project daemon records, a real `daemon.port`, an HTTP auth token, connect-first activation, `noir init`/`--upgrade` completeness, and the `.noir/.env` precedence inversion with provenance. — **MET** (1.14.0).
- **v1.15.0 — env templates + `noir init --upgrade` completeness + provider gateways + `noir run` UX** (ADR-0012): the two-template split carried by a scaffold migration, stale-seed refresh on upgrade, provider transport fields (`authTokenEnv`, `timeoutMs`) with ambient-env neutralization, and the `noir run` status line / palette argument collection / TUI run mode / post-run actions / interrupt contract. — **MET** (1.15.0).
- **v1.16.0 — display integrity + workspace stdio transport + permission contract + output hygiene** (ADR-0013): one shared display-width module as the single text-measurement authority (ANSI stripped, East-Asian wide measured as 2, no split surrogate pairs) with container-derived width budgets, the workspace stdio bridge replacing the `?p=` URL (with `400`/`405` routing and `/health` ownership proofs), the `0600` permission contract for `.noir/.env` and an owner-only store, and the output-hygiene subsystem (a tiered rule source through `noir skills lint` + `noir doctor` + a CI gate, and the `noir-code-hygiene` builtin). — **MET** (1.16.0).

## How to use this file

- **When shipping a version:** add the release to `CHANGELOG.md` (root); the release registry (`.noir/releases/`) is updated automatically by CI on publish — run `pnpm release:history` to view it and `pnpm release:rebuild` to regenerate it locally; advance the "Current status" block and version targets here.
- **When direction changes:** update the vision + version targets, and record the *why* as an ADR in `docs/decisions/`.
- **When tempted to add scope:** check the Deferred table — if it is listed, it is intentional; add new deferrals here rather than dropping them silently.
